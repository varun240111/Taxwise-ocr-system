profile_complete field is the key flag. When ProtectedRoute checks this, it decides: go to /dashboard OR redirect to /profile-setup. It's set to true only after the user finishes the 4-step onboarding wizard.
refresh_token in MongoDB = server-side logout. On logout, set this to null. Even if someone stole the cookie, the backend rejects it because the DB value is null now.
OTP Collection (separate, TTL index)
Store OTP in a separate collection with a MongoDB TTL index on expires_at. Set expiry to 10 minutes. MongoDB auto-deletes the document when it expires — no cron job needed.

2.3
Login → JWT Tokens → HTTP-only Cookie Set
Creates two tokens: Access Token (15 min, returned in JSON) and Refresh Token (7 days, set as HTTP-only cookie). React stores access token in Redux memory only — never localStorage.
jscontrollers/authController.js — login
const login = async (req, res) => { const { email, password } = req.body const user = await User.findOne({ email }) if (!user) return res.status(404).json({ error: 'Not found' }) const ok = await bcrypt.compare(password, user.password_hash) if (!ok) return res.status(401).json({ error: 'Wrong password' }) // ACCESS TOKEN — 15 minutes const accessToken = jwt.sign( { userId: user._id, email: user.email }, process.env.JWT_SECRET, { expiresIn: '15m' } ) // REFRESH TOKEN — 7 days const refreshToken = jwt.sign( { userId: user._id }, process.env.JWT_REFRESH_SECRET, { expiresIn: '7d' } ) // Save refresh token in MongoDB user.refresh_token = refreshToken user.last_login = new Date() await user.save() // SET COOKIE — HTTP-only, JS cannot read this res.cookie('refreshToken', refreshToken, { httpOnly: true, secure: true, sameSite: 'strict', maxAge: 7 * 24 * 60 * 60 * 1000 }) // Return access token + user info to React res.json({ accessToken, user: { id: user._id, name: user.name, email: user.email, profile_complete: user.profile_complete } }) }
Redux authSlice — what React stores

// On successful login dispatch(setAuth(data)) const authSlice = createSlice({ name: 'auth', initialState: { token: null, // access token in memory user: null // name, email, profile_complete }, reducers: { setAuth: (state, { payload }) => { state.token = payload.accessToken state.user = payload.user }, clearAuth: (state) => { state.token = null state.user = null } } })
Axios interceptor — silent token refresh
When any API call returns 401 (expired), the Axios interceptor automatically calls POST /auth/refresh (which reads the cookie), gets a new access token, updates Redux, then retries the original request. User never sees an error or a login screen.
After login: React checks user.profile_complete. If false → navigate('/profile-setup'). If true → navigate('/dashboard'). This is the critical branch that matches the flowchart.

PHASE 05 Rule Engine — Pure Tax Calculation (Old + New Regime) utils/taxEngine.js · Called by Node.js backend
5.1
Full Tax Engine — HRA + All Deductions + Both Regimes + Gap Detection
100% deterministic pure functions. No ML here. Same inputs always give same result. This runs on every profile save and every calculate button click.
jsutils/taxEngine.js
// ── HRA: minimum of 3 formulas ────────────── function calcHRA(p) { if (!p.deductions.is_rented) return 0 const rent = p.deductions.rent_monthly * 12 const basic = p.salary.basic_annual const hraRcvd = p.salary.hra_received_annual const pct = p.personal.city_type === 'metro' ? 0.50 : 0.40 return Math.max(0, Math.min( hraRcvd, // Formula 1 rent - (0.10 * basic), // Formula 2 pct * basic // Formula 3 )) } // ── 80D limit (changes if parents are senior) ── function calc80D(p) { const maxSelf = 25000 const maxParents = p.life_events.parent_senior ? 50000 : 25000 return ( Math.min(p.deductions.insurance_self, maxSelf) + Math.min(p.deductions.insurance_parents, maxParents) ) } // ── Old Regime tax slabs ───────────────────── function oldRegimeTax(ti) { // ti = taxable income let t = 0 if (ti <= 250000) t = 0 else if (ti <= 500000) t = (ti-250000) * 0.05 else if (ti <= 1000000) t = 12500 + (ti-500000) * 0.20 else t = 112500 + (ti-1000000) * 0.30 return Math.round(t * 1.04) // +4% cess } // ── New Regime tax slabs (FY 2024-25) ──────── function newRegimeTax(ti) { let t = 0 if (ti <= 300000) t = 0 else if (ti <= 700000) t = (ti-300000) * 0.05 else if (ti <= 1000000) t = 20000 + (ti-700000) * 0.10 else if (ti <= 1200000) t = 50000 + (ti-1000000) * 0.15 else if (ti <= 1500000) t = 80000 + (ti-1200000) * 0.20 else t = 140000 + (ti-1500000) * 0.30 return Math.round(t * 1.04) // +4% cess } // ── MAIN function — run this on every calculate ── function runTaxEngine(profile) { const gross = profile.salary.gross_annual const hra = calcHRA(profile) const c80 = profile.deductions.total_80c // already capped at 1.5L const d80d = calc80D(profile) const nps = Math.min(profile.deductions.nps_contribution, 50000) const s24 = Math.min(profile.deductions.home_loan_interest, 200000) const edu = profile.deductions.edu_loan_interest // no cap const donations= profile.deductions.donations_80g * 0.5 // 50% deductible const stdOld = 50000 const stdNew = 75000 const totalDeductionsOld = c80+d80d+hra+nps+s24+edu+donations+stdOld const taxableOld = Math.max(0, gross - totalDeductionsOld) const taxableNew = Math.max(0, gross - stdNew) const taxOld = oldRegimeTax(taxableOld) const taxNew = newRegimeTax(taxableNew) // 80D limit depends on life events const max80d = 25000 + (profile.life_events.parent_senior ? 50000 : 25000) return { hra_exemption: hra, tax_old_regime: taxOld, tax_new_regime: taxNew, recommended_regime: taxOld <= taxNew ? 'old' : 'new', gap_80c: Math.max(0, 150000 - c80), gap_80d: Math.max(0, max80d - d80d), gap_nps: Math.max(0, 50000 - nps), potential_saving: Math.abs(taxNew - taxOld), calculated_at: new Date() } } module.exports = { runTaxEngine, calcHRA, calc80D }
This function returns the gaps (gap_80c, gap_80d, gap_nps) which become the MOST IMPORTANT input features for the ML model in Phase 6.
Where runTaxEngine is called
  • After salary is saved — auto-calculate immediately
  • When user updates any deduction field
  • When a life event is logged
  • When user clicks "Recalculate" on dashboard
  • Result always stored in user_profiles.tax_result

Alerts System + Life Events Engine
Alerts — MongoDB alerts collection
  • Created when profile is saved or updated
  • Types: deadline_80c, hr_submission, insurance_renewal, nps_gap, itr_deadline
  • Each has: user_id, type, message, deadline_date, is_read (default false)
  • Dashboard API fetches top 5 unread sorted by deadline_date
  • Nodemailer (email) + Twilio (SMS) send reminders at 60/30/15/7 day marks
  • A cron job (node-cron) runs daily at 9am, checks all alerts, sends due ones
Cron job setup
cron.schedule('0 9 * * *', checkAndSendAlerts)
Runs at 9:00 AM IST every day. Fetches all unread alerts where deadline is within 60 days. Sends email/SMS. Never sends same alert twice — has sent_at field.
Life Events — trigger recalculate

Next Year ML Prediction — April Planning
1Triggered April 1 each year OR when user clicks "Plan Next Year" on dashboard
2Fetch current year final salary, all investments, life events, feedback given
3Calculate salary growth rate: (this year − last year) / last year × 100
4Estimated next year salary = current × (1 + growth_rate)
5Run tax engine with estimated salary → find new gaps
6Send to Flask ML → get suggested instruments for next year profile
7Generate month-by-month SIP plan: gap_80c / 12 = monthly ELSS/PPF amount
